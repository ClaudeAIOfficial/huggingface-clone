NVIDIA Pets: Interactive Multi-Agent Digital Companions with Autonomous Behavior and Local Memory

Released October 2026 · NVIDIA Pets project
Authors: Independent NVIDIA Pets project contributors
Robotic companionsMulti-agent systemsInteractive simulationBrowser-based

Abstract

NVIDIA Pets is a browser-based digital companion prototype that explores how independent robotic-animal characters can display movement, personality-specific responses, and memory within a shared interactive environment.

The project demonstrates a lightweight multi-agent architecture using a penguin and a turtle character as visual companions. Both agents maintain distinct behavior settings and conversation state, while a shared rendering loop coordinates their movement in the browser. Users can select a companion, communicate through text, and trigger interactions such as moving, playing, resting, and following the cursor. The prototype emphasizes expressive character behavior and the sense of companionship without requiring a continuously running model server. The implementation stores conversation history locally and uses predefined dialogue rules rather than a trained language model. The accompanying visual demonstration illustrates the two robotic characters, their common design language, and restrained animated behavior.

1. Introduction

Personal assistants typically live in a chat interface and wait for direct instructions. NVIDIA Pets explores a different presentation: small, animal-inspired companions that share a visual space with the user, perform autonomous movements, and maintain their own interaction patterns. The interaction design draws inspiration from physical robots, particularly expressive optical eyes, compact mechanical proportions, and simple recognizable motions.

The goal of this prototype is to study how a small number of independent behaviors can make a digital companion feel responsive without introducing complicated simulation requirements. The current implementation runs entirely in the browser, and its behaviors do not imply physical robot autonomy or a deployed foundation model.

2. System Architecture

Each companion is represented by an independent agent object. The agent contains a personality profile, position, movement target, idle state, energy and happiness values, and a separate message history. A shared animation loop advances the positions of all active agents, while event handlers react to clicks, cursor motion, dragging, and interaction controls.

2.1 Movement and Behavior

Each agent periodically chooses a destination and moves toward it with a configurable speed. Additional modes temporarily replace autonomous roaming: a rest interval pauses movement, a play action increases activity, and a follow action redirects the target toward the user's cursor. Pointer input allows the user to reposition agents directly. The mechanism favors clear, visually legible behavior over complex physical simulation.

2.2 Distinct Companion Personalities

Personality profiles influence greetings, response selection, idle behavior and interaction patterns. The penguin companion favors curious, exploratory behavior. The turtle companion favors calm, measured actions. Their differentiation comes from lightweight behavioral settings and scripted response styles, rather than a claim of independent consciousness or human-level conversational intelligence.

2.3 Persistence and Memory

Conversation histories and selected profile information can persist in browser local storage. Keeping individual state separate prevents one companion's discussion from automatically becoming another's memory. Local persistence removes the need for a hosted account system in this early prototype, but it also means memories do not synchronize across devices and can disappear when browser storage is cleared.

3. Interactive Demonstration

The browser playground supports four basic classes of input: selecting an agent, sending a text message, moving the agent in a shared scene, and choosing an interaction action. The same interaction controls can be expanded to new characters or richer behaviors without altering the overall scene structure.

Current implementation: Users can move and interact with digital sprites. The project does not yet provide 3D skeletal rigs, an always-on-top desktop overlay, voice interaction, or hosted language-model inference.

4. Implementation Details

The prototype uses HTML, CSS and JavaScript. Character artwork starts from realistic 3D-style renders and is displayed as 2D sprites. A frame-driven renderer handles movement and positioning, while local dialogue logic produces character-specific responses. Client-side storage retains each character's conversation history. Source code and manifest files are available in the associated repository.

Interaction pseudocode
for (const pet of activePets) {
  pet.updateAutonomousTarget();
  pet.moveTowardTarget(deltaTime);
  pet.render();
}

onMessage(pet, message) {
  pet.history.push(message);
  pet.replyUsingLocalPersonalityRules();
  pet.saveHistory();
}

5. Evaluation and Limitations

This release is a demonstration of interaction design and browser behavior, not a published benchmark study. It contains no measured robotics success rates, physical hardware test results, or statistical comparison against commercial assistant systems. Any future evaluation should explicitly report its procedure, sample size, hardware or simulator configuration, and limitations.

The CGI companion video is intended to visualize the character designs and potential behaviors. It should not be interpreted as evidence that physical NVIDIA Pets devices exist or that the characters use production-grade autonomous AI.

6. Future Work

Potential extensions include rigged 3D models with articulated walk cycles, sound and speech synthesis, optional language-model reasoning through a secure service, user-controlled memory, cross-companion collaboration and a true desktop companion application. Each improvement can build on the prototype's separate agent states and shared scene controls.
